# Gammal Tech Integration Demo 🚀

هذا المشروع هو عرض تجريبي (Demo) لاستخدام حزمة تطوير البرمجيات الخاصة بـ **Gammal Tech SDK v3.0.1**. يركز المشروع على تطبيق عملي لنظام حجز أطباء.

## ✨ المميزات المنفذة
- **🔐 تسجيل الدخول:** باستخدام Gammal Tech Passport.
- **🔍 البحث عن الأطباء:** واجهة تفاعلية للبحث عن الأطباء من قائمة بيانات.
- **💳 نظام الدفع:** تكامل مع محفظة جمال تك (EGP) لحجز المواعيد.
- **📦 تخزين البيانات:** حفظ سجل الحجوزات الخاص بالكل مستخدم ومزامنته عبر `GammalTech.user`.
- **🤖 المساعد الذكي:** شات بوت طبي تفاعلي.

## 🛠️ التقنيات المستخدمة
- HTML5 / CSS3 / JavaScript
- Gammal Tech Web SDK

## 🚀 كيفية التشغيل
1. قم بتحميل الملفات.
2. افتح ملف `index.html` في المتصفح.
3. تأكد من تشغيل المشروع على `localhost` أو دومين معتمد في لوحة تحكم المطورين الخاصة بجمال تك.

## 🔗 الدوال المستخدمة من الـ SDK
- `GammalTech.pay()`: لإتمام عملية الدفع.
- `GammalTech.payment.confirmDelivery()`: لتأكيد إتمام الخدمة.
- `GammalTech.user.save()`: لحفظ بيانات الحجز.
- `GammalTech.payment.settlePending()`: لاستعادة العمليات المعلقة.

## 🔐 قرارات الأمان (Security Decisions)

تم بناء هذا المشروع مع مراعاة أعلى معايير الأمان التي توفرها حزمة Gammal Tech SDK، وفيما يلي تفصيل للقرارات التقنية المتخذة:

### 1. الأمان القائم على المجال (Domain-Based Security)
* **لماذا لا نستخدم مفاتيح API؟** مفاتيح API التقليدية المعرضة للعميل (Client-side) يمكن سرقتها بسهولة من كود المصدر. لذا، يعتمد الـ SDK على **التحقق من المجال (Domain Whitelisting)**.
* **الفائدة:** يضمن هذا أن الطلبات لا تُقبل إلا من النطاقات المعتمدة (مثل `localhost` أو رابط موقعك الرسمي)، مما يمنع المهاجمين من انتحال هوية تطبيقك لإجراء عمليات مشبوهة.

### 2. التعامل مع بيانات الجلسة (Session Management)
* **الآلية:** يتم تشفير بيانات الجلسة وإدارتها داخلياً بواسطة الـ SDK والارتباط بـ **Gammal Tech Passport**.
* **التنفيذ:** نستخدم دالة `GammalTech.isLoggedIn()` قبل كل عملية حساسة (مثل الدفع أو جلب البيانات الخاصة). هذا يضمن عزل بيانات المستخدمين لكل مطور (Per-Developer Isolation)، بحيث لا يمكن لأي تطبيق آخر الوصول لبيانات تطبيقك.

### 3. استراتيجية إدارة أخطاء واجهة برمجة التطبيقات (API Error Handling)
* **رد الفعل:** عند حدوث خطأ من الـ API، يقوم التطبيق بتحليل رمز الخطأ (Error Code) وعرض رسالة مناسبة للمستخدم:
    * في حالة `INSUFFICIENT_BALANCE`: يتم توجيه المستخدم لشحن المحفظة.
    * في حالة انقطاع الاتصال: نستخدم ميثود `GammalTech.payment.settlePending()` عند تحميل الصفحة لاستعادة وتأكيد أي عمليات دفع لم تكتمل، مما يضمن عدم ضياع أموال المستخدم أو حقوق المطور.
